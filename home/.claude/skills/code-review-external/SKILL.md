summary: 外部プロセス(codex または claude または gemini)を使用してコミット済みのコードをレビュー・修正させ、結果を検証します
argument-hint: "[--claude|--codex|--gemini] [-a|--adversarial] [target_revision] (default: codex, target: origin/main...HEAD)"
---

以下の手順に従って、コミットされたコードの外部レビュー、修正、およびその検証を行ってください。

【重要】
外部プロセスを起動する前に `external-agent-invocation` スキルを読み、オプションの解釈・コマンドの形・落とし穴・重大度の書かせ方はそちらに従ってください。このスキルには、コードレビューに固有の部分だけを書いています。

- **重大度のラベル**: 「ブロック」（マージを差し止めるべき重大な問題）/「非ブロック」（改善提案レベル）
- **外部プロセスに修正まで適用させます**。claude を使う場合は編集を許可する起動にしてください。

【手順】
1. **未コミット変更の確認とコミット**:
   - `git status` を実行し、未コミットの変更があるか確認してください。
   - 変更がある場合は、レビューを開始する前にまずそれらをコミットしてください。
   - コミットメッセージは、レビュー担当者が「何のために何をしたのか」を正確に把握できるよう、変更の背景、目的、および具体的な内容を論理的かつ簡潔に記述してください。
   - コミットが完了したら、その最新のコミットを対象として以降の手順を進めてください。

2. **TARGET_REVISION の特定**:
   - `{{args}}` からオプションフラグを除いた部分を対象リビジョンとします。
   - 除いた結果が空（指定なし）の場合は、デフォルトとして `origin/main...HEAD` を使用してください。
   - 単一のコミットハッシュだけでなく、`origin/main...feature` のようなコミット範囲や、`HEAD~3` のような相対指定も受け入れられるようにします。

3. **変更の位置づけの特定**:
   - この変更が今どの段階にあるか（試作・検証中なのか、マージ直前なのか）と、行き先（どのブランチへ入るか）を、依頼コンテキストから特定してください。不明な場合はユーザに確認してください。

4. **外部レビューと修正の依頼**:
   - **プロンプトに含める指示内容**:
     ```
     【変更の位置づけ】
     [段階と行き先を1〜3行で記載。例: 「マージ直前の最終確認。この後 origin/main へ入る」]
     重大度（ブロック/非ブロック）は、この位置づけにおけるマージ可否を基準に判定してください。

     指示:
     1. `git log -p [TARGET_REVISION]` または `git show [TARGET_REVISION]` を実行して、含まれる全ての変更内容を [判定したモードに応じて "Adversarial Review" または "レビュー"] してください。
     2. セキュリティ、パフォーマンス、可読性、アーキテクチャの観点からレビューを行ってください。
     3. 改善点が見つかった場合、利用可能なツールを使って該当ファイルを直接編集し、修正を適用してください。
     4. どのような問題をどのように修正したか、実行結果として簡潔に出力してください。
     5. 各指摘には重大度として「ブロック」か「非ブロック」かを必ず明記してください。ブロックに該当する指摘が一つも無い場合は「ブロックレベルの指摘なし」と明記してください。
     ```

5. **修正内容の検証**:
   - 外部プロセスによる処理が完了した後、`git diff` を実行し、ワークツリーにどのような変更が加えられたかを確認してください。
   - 変更内容（diff）を読み取り、以下の点を目視（静的分析）でチェックしてください。
     - 元のコードの意図が壊れていないか
     - 新たなバグや構文エラーが混入していないか
     - プロジェクトの規約に反していないか
   - 検証結果（変更の妥当性、問題の有無）をユーザーに報告してください。問題があればどのように直すべきかも提案してください。報告冒頭でのブロックレベルの明示は共通手順のとおりです。
