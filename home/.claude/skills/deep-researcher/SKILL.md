# deep-researcher

質問を複数の角度に分解して web を広く調べ、集めた主張を反証役のエージェントに検証させ、生き残った内容だけで日本語のレポートを組み立てて HTML に起こす。

**Claude Code 専用。** 実体は Workflow ツールで動く JavaScript（`scripts/workflow.js`）であり、Workflow ツールを持たないエージェントでは動かない。

**エージェント起動数が多い（標準で 100 回前後）。** ユーザーが明示的に呼び出したときだけ動かす。

## 手順

### 1. 質問を絞る

渡された内容が、そのまま調べられるだけ具体的かを確かめる。
予算・用途・対象バージョン・地域・時点など、答えが大きく変わる条件が欠けているなら、AskUserQuestion で**2〜3問だけ**聞いて補う。聞いた答えは質問文そのものに織り込む。

すでに具体的なら、何も聞かずに次へ進む。

### 2. 規模を決める

引数に規模の指定があればそれに従う。なければ `standard`。

| 指定 | depth | 角度 | 取得ページ | 検証の票数 | 検証する主張 |
|---|---|---|---|---|---|
| 軽め / light | `light` | 3 | 8 | 1 | 12 |
| 指定なし / 標準 / standard | `standard` | 5 | 15 | 3 | 25 |
| 徹底 / deep | `deep` | 6 | 25 | 5 | 40 |

票数は反証役の人数で、過半数が反証すればその主張は棄却される。`light` は1票なので、1人が反証しただけで落ちる代わりに誤りも残りやすい。

### 3. ワークフローを走らせる

```
Workflow({
  scriptPath: "${CLAUDE_SKILL_DIR}/scripts/workflow.js",
  args: { question: "<手順1で絞った質問>", depth: "standard" }
})
```

`args` はオブジェクトのまま渡す（JSON 文字列にしない）。

ワークフローは Scope（角度分解）→ Search（web 検索と context7）→ Fetch（ページ取得と主張の抽出）→ Verify（反証の多数決）→ Synthesize（統合）の順に進み、構造化データを返す。

### 4. レポートを Markdown にまとめる

返ってきたデータを、スクラッチパッドに Markdown として書き出す。ファイル名は `deep-research-<話題を表す短い英字>.md`。

載せる内容:

- 調査依頼と規模（`question`、`depth`）
- 要約（`summary`）
- 知見（`findings`）— 確信度、根拠、情報源の URL つき
- 注意点（`caveats`）
- 未解決の問い（`openQuestions`）
- **棄却された主張**（`refuted`）と**判定できなかった主張**（`unverified`）— 落とさずに必ず載せる。何が否定されたかは、何が支持されたかと同じだけ重要
- 情報源の一覧（`sources`）— 質の格付きで
- 集計（`stats`）— 角度数、取得数、抽出した主張数、支持・棄却・判定不能の内訳

`stats.claimsOverCap` が 0 より大きいときは、上限を超えて検証されなかった主張がその件数あることを注意点に書く。`stats.budgetDropped` も同様に、取得を見送ったページ数として書く。

### 5. HTML にする

`visualize` スキルを呼び、手順4で書いた Markdown のパスを渡す。HTML の体裁と保存先は `visualize` 側に任せる。

ユーザーには、出来上がった HTML のパスと、要約を数行だけ伝える。

## 守ること

- **引用は原文のまま。** 主張の文面は日本語にするが、裏付けの引用は翻訳しない。あとから裏を取れなくなるため。ワークフロー側にもそう指示してあるので、レポートに写すときも訳さない。
- **落ちた主張を隠さない。** 棄却・判定不能はレポートに残す。都合のよい結論だけを見せない。
- **検証できなかった回は、そう言う。** 反証役が全員エラーで落ちた場合、ワークフローは「調査の結論ではなく実行環境の障害」と明示した要約を返す。これを成果として報告せず、そのまま伝えて再実行を促す。

## 変更するとき

`scripts/workflow.js` を直接編集する。書き方の決まり（`meta` はリテラルのみ、`Date.now()` や `Math.random()` は使えない、`pipeline()` を既定にするなど）は `workflow-authoring` スキルに従う。

web ページ由来の文字列を無害化する処理（`URL_HOST_PATTERN`、`LABEL_STRIP`、`webText`、`WEB_NOTE`）は、表示の偽装とプロンプトへの命令混入を防ぐためのもの。理由をコメントに残してあるので、読まずに削らない。
