# SKILL.md シェルコマンドルール

### ホームディレクトリは `~` を使う

絶対パスは環境によってユーザー名が変わるため、`~` を使う。

### 作業ディレクトリは `cd` ではなくコマンド引数で指定する

`cd <path> && git ...` のように**複合コマンドの先頭へ `cd` を置かない**。git は `git -C <path>`、task は `task -d <path>`、読み取りはパス指定で対象を渡す。

```bash
git -C ~/Documents/memos log -1 --format="%H" -- <file>
```

**なぜ**: auto mode では、`cd` の後ろの相対パスは検索先を確定できないと判定され、`Read()` の拒否ルールが1本でもあると承認ダイアログになる。拒否ルールの確認は許可リストより先に立つため、`Bash(grep:*)` のような許可を足しても防げない。人が承認できない実行形態（定期実行・バックグラウンド）では、ここで静かに止まる。

**この節は 2026-09-22 に反転した。** 以前は「`git -C` は権限プロンプトでブロックされるケースがあるので `cd <path> && git` を使う」と書いていたが、その主張には根拠も観測記録も無く、一方で `cd` 側の挙動には実測と機構の特定がある。

ただし `git -C` がプロンプトを誘発する構成があり得ること自体は否定されていない（許可リストが `Bash(git log:*)` のような前方一致で書かれていると `git -C <path> log` に当たらない、という筋は未確認）。**`git -C` で止まる事例に遭遇したら、そのときの許可設定とモードを添えてこの節へ書き足す** — どちらの向きも、観測を伴わない断定にしない。
